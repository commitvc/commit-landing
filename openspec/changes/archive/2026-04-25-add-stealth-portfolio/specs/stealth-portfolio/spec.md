## ADDED Requirements

### Requirement: `Company.stealth?: boolean` flag marks an entry as stealth

The `Company` type in `lib/companies.ts` SHALL include an optional `stealth?: boolean` field. When `true`, every site surface that touches the entry SHALL apply the stealth treatment defined in this spec.

#### Scenario: type-level field

- **WHEN** the `Company` type is read
- **THEN** it includes `stealth?: boolean` (optional)

#### Scenario: stealth = true triggers all rules below

- **WHEN** any `Company` instance has `stealth: true`
- **THEN** the rules in this spec apply uniformly across the card render, file tree, JSON-LD, ItemList, OG metadata, and llms.txt presentation

### Requirement: Stealth Fund I entries live under `/companies/<slug>/` and use `folder: 'active'`

Stealth entries SHALL declare `folder: 'active'` so their URL space is `/companies/<slug>/`, not `/companies/pre-commit/<slug>/`. The fund pre-commit category is by definition disclosed historical investments and never carries stealth markers.

#### Scenario: stealth entry route

- **WHEN** a stealth `Company` is added with `slug: 'inference'`
- **THEN** the static route generated by `app/(chrome)/(tabs)/companies/[slug]/page.tsx` is `/companies/inference/`

### Requirement: The slug carries the only deliberate domain tease

The stealth entry's `slug` SHALL be the only sanctioned channel through which the public learns the deal's domain. Filename `<slug>.txt` appears in the `/companies/` file tree; URL `/companies/<slug>/` is in the sitemap. The `oneLiner` field SHALL expand the slug into a phrase (e.g., `AI inference stack`) but SHALL NOT add further identifying detail (no founder names, no location, no investor list, no funding-round timing).

#### Scenario: stealth entry minimal data

- **WHEN** a stealth Company is declared
- **THEN** `company` is the literal string `'Stealth'`, `avatar` is `''`, and the `oneLiner` describes only the domain space — not the company name, not the founders, not the location

### Requirement: `CompanyCard` renders a single-line `Permission denied` block for stealth entries

When `company.stealth === true`, `CompanyCard` SHALL early-return a `StealthCard` whose body is a single `<p>` element containing `<filename>: Permission denied`. No `# about` section, no `# project` section, no metadata grid, no link row, no avatar.

#### Scenario: StealthCard structure

- **WHEN** `/companies/inference/` is rendered
- **THEN** the article body contains exactly one `<p>` with text `inference.txt: Permission denied` (filename in `--fg`, message in `--fg-muted-hover`)

#### Scenario: no project / about / metadata sections

- **WHEN** any stealth page is rendered
- **THEN** the rendered HTML contains no `# about` heading, no `# project` heading, no `<dl>` metadata grid, and no link row

### Requirement: File tree displays stealth entries in muted green

`FileTree.tsx` SHALL apply a `fileStealth` class to file-tree entries whose slug matches a `Company` with `stealth: true`. The class declares `color: rgba(158, 206, 106, 0.55)` — the regular green `.file` colour at ~55% alpha. No italic, no opacity on the wrapper button.

#### Scenario: stealth file is muted

- **WHEN** a user views the `/companies/` file tree
- **THEN** `inference.txt` and `specs.txt` render with the muted-green colour, while `uma.txt` and `pre-commit/<slug>.txt` files render with the standard green

### Requirement: Stealth detail pages emit no Organization JSON-LD

`app/(chrome)/(tabs)/companies/[slug]/page.tsx` SHALL skip emitting the Organization JSON-LD `<script>` block when `company.stealth === true`. BreadcrumbList JSON-LD SHALL still emit (for navigation context).

#### Scenario: no Organization on stealth detail

- **WHEN** the rendered HTML of `/companies/inference/` is parsed for JSON-LD blocks
- **THEN** no block has `"@type": "Organization"` whose `name` is "Stealth"
- **AND** at least one block has `"@type": "BreadcrumbList"`

#### Scenario: Organization remains the page-level node from layout

- **WHEN** the rendered HTML of any stealth page is parsed
- **THEN** the root `Organization` node from `app/layout.tsx` IS present (the page-level Org for `>commit` is not the per-entry Org for the company; the per-entry one is what's suppressed)

### Requirement: Stealth entries are excluded from the active-companies ItemList

`lib/structured-data.ts` `activeCompaniesItemList()` SHALL filter out entries with `stealth: true`. The pre-commit ItemList is unaffected (no pre-commit entry can have `stealth: true` per Decision 1).

#### Scenario: ItemList excludes stealth

- **WHEN** the rendered HTML of `/companies/` is parsed for the `">commit Fund I portfolio"` ItemList
- **THEN** no `ListItem` has a `url` ending in `/companies/inference/` or `/companies/specs/`

#### Scenario: pre-commit ItemList unaffected

- **WHEN** the `"Companies the >commit team backed before the fund"` ItemList is parsed
- **THEN** it contains every pre-commit entry, regardless of any stealth flag (none have it today; the rule documents the invariant)

### Requirement: Stealth pages declare a teaser description and skip the OG image

`generateMetadata` for `/companies/[slug]/` SHALL produce, when `company.stealth === true`:

- `description`: `Stealth Fund I investment — <oneLiner>. Disclosure pending.`
- `openGraph.images`: omitted (the avatar is empty, no fallback to `/card.png`)
- `title`: `<company> — <oneLiner>` (so the page `<title>` is `Stealth — AI inference stack | >commit`, deliberately teasing the domain)

#### Scenario: stealth description format

- **WHEN** the `<meta name="description">` of `/companies/inference/` is read
- **THEN** it is `Stealth Fund I investment — AI inference stack. Disclosure pending.`

#### Scenario: no OG image for stealth

- **WHEN** the OG metadata of `/companies/inference/` is parsed
- **THEN** `og:image` is absent on the page-level metadata (the layout-level shared `/card.png` may still inherit; the page does not declare its own)

### Requirement: `/llms.txt` lists stealth entries with explicit "Identity disclosed at launch." tag

The Portfolio section of `/llms.txt` SHALL list each stealth entry on its own line, with description ending in the literal text `Identity disclosed at launch.`

#### Scenario: stealth entries in llms.txt

- **WHEN** the Portfolio (>commit Fund I) section of `/llms.txt` is parsed
- **THEN** lines for `/companies/inference/` and `/companies/specs/` exist, each with description ending in `Identity disclosed at launch.`

### Requirement: Homepage SSR thesis declares the active commitment count

The sr-only block on `/` (covered in detail by the `ssr-fallback-content` capability) SHALL include a single sentence stating the count of active Fund I commitments and how many are stealth.

#### Scenario: count line on homepage

- **WHEN** the sr-only block of `/` is read
- **THEN** at least one paragraph contains a sentence of the form "Active Fund I commitments to date: N — one announced (UMA — humanoid robotics), two stealth (disclosure pending)" (or semantically equivalent, with the count updated as new entries land)
